Makes "a finite-dimensional inner product space over $\mathbb{R}$ or $\mathbb{C}$ is complete" an instance, so `CompleteSpace E` no longer has to be introduced by hand with `haveI := FiniteDimensional.complete 𝕜 E`. With the instance available, the PR deletes those local `have`s from statements and proofs about the adjoint of linear maps between finite-dimensional inner product spaces (`LinearMap.adjoint` and its API) and from `LinearMap.IsPositive.conj_adjoint`.

## *

Cleanup: the declaration's statement and proof are unchanged except that a local `have`/`haveI := FiniteDimensional.complete 𝕜 E` (and the one for `F`) was deleted. When it sat inside the statement (e.g. `adjoint_toContinuousLinearMap`, `isSelfAdjoint_toContinuousLinearMap_iff`), the statement is the same proposition, now elaborated with the new instance `InnerProductSpace.completeSpaceOfFiniteDimensional`. `adjoint` also loses its long comment about universe metavariables, which no longer applies. What to check: nothing beyond the new instance.

## _root_.InnerProductSpace.completeSpaceOfFiniteDimensional

Instance: an inner product space $E$ over an `RCLike` field $\mathbb{K}$ ($\mathbb{R}$ or $\mathbb{C}$) that is finite-dimensional over $\mathbb{K}$ is complete.

**Definition.** Directly `FiniteDimensional.complete 𝕜 E`.

**Check.** It is declared inside `namespace ContinuousLinearMap`, where `variable [CompleteSpace E]` is in scope, and has no `omit [CompleteSpace E] in` (the very next theorem needs one). Confirm with `#check @InnerProductSpace.completeSpaceOfFiniteDimensional` that it did not pick up `[CompleteSpace E]`, which would make it circular. Also, `𝕜` does not appear in the goal `CompleteSpace E`, so instance search has to guess it. This is why `FiniteDimensional.complete` was not an instance before. Check that the `dangerousInstance` linter accepts it and that it does not slow down `CompleteSpace` searches. Adjoint.lean is an odd home for a general instance: a basic inner-product-space file would fit better.
